## 开立新项目

每个项目至少应明确**项目 ID、slug、一句话主旨、目标观众、交付物、数据/素材来源、验证办法、当前阶段、执行设备和禁止操作边界**。复制 [_template](./_template/) 内的 `README.md` 与 `PROJECT_CHARTER.md`，再添加创意和制作文件；未经实际创建，不在索引中凭空登记计划中项目。

每个项目按需独立维护：

| 文件或目录 | 职责 |
| --- | --- |
| `PROJECT_CHARTER.md` | 不随版本改来改去的**项目主旨与边界**、受众、编辑承诺、完成定义 |
| `README.md` | 当前阶段、版本、接手路径，最短导航 |
| `CREATIVE_BRIEF.md` | 创作探索、叙事和美学参考，可保留早期历史版本 |
| `PRODUCTION_PLAN.md` | 当前/历史里程碑、制作闸门和验收清单 |
| `data/`, `research/`, `reference/` | 数据、研究与参考；显式标注事实强度和来源许可 |
| `remotion/` 或其他项目独立工程 | 代码、锁文件、渲染命令、V1/V2 映射、输出说明 |
| `content/` | 可复用文案和内容组件；不要把未验证主张直接包装为官方结论 |

## 状态和版本

`IDEA` 想法；`PLANNED` 已立项；`BUILDING` 制作中；`REVIEW` 候选成片待审；`PUBLISHED` 已公布并记录链接；`ARCHIVED` 归档。状态由实际证据决定，不能把“代码已推 GitHub”当作“发布完成”。

保留各版本 SHA 和构建方式。历史 V1/V2 不通过改写 commit 或模糊命名“当前版”来覆盖。多个项目可以共同复用成熟的通用组件，但必须有明确的共享接口与授权，不应因为用了同一个仓库就默认混装依赖和缓存。

**禁止越界：** 不在一个项目的工作流顺手修改其他项目、`main` 或生产服务。每个项目另行声明自己的设备、隐私、版权和数据留存约束；所有高风险操作必须得到相应授权。
