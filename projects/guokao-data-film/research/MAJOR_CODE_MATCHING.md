完整保留 T/K/TK 和内部字母，例如 `030108TK`、`020311TK`、`0814Z2`。当前本科目录还有 `0502100T` 等七位数字加后缀代码。检索键可转大写，原文与字元位置保留。

## 解析做了什么

1. 根据本科、大学本科、研究生等标记切分学历，包括无分号的学历切换。
2. 同时识别代码在名称之前、之后和括号内的完整词元；每处提及保存原文位置。
3. 在相容学历目录中查代码，分别标记单一候选、目录歧义与未解义。
4. 名称按完整名称连接，保留括注、方向、排除和相关专业等开放表达。同一短语有明确代码时，同名候选限于该代码，避免“0301法学”误扩成“03法学”大门类。
5. 同一岗位同一代码去重；不同代码的人数不能直接相加。

全部词元及岗位集合已与独立提取程序对照，每个字符位置都可还原原文。字元位置使用 Python Unicode code point 索引。

单条要求的 `review_reasons` 是复核入口。某个词元的 `condition_requires_review=false` 只表示局部没有命中相关标记，不能覆盖整条要求的多学历、歧义等复核原因。独立读取验证了 5,983 处代码跨度、5,014 处分句跨度及 8 类真实表达回归。

## 税务类别

税务官方目录有 53 类别、849 条成员关系。目录未逐项提供学历或教育部代码，因此成员的 code 和 education_level 保持空值。

“经济统计学”属于税务经济学类和统计学类，两条边都保留。税务类别与教育部同名类别也不合并。

`tax-catalog-name-crosswalk.json` 保存税务成员名称与教育部目录的精确名称候选连接。这不是学历等价或完整报考资格的证明。本科类别可沿官方父子关系展开，税务沿自己的成员关系展开；排除、方向和其他条件仍须同时解释。

```js
const data = await loadMajorData();

const law = data.findExplicitCode('030101K');
// law.positions === 329; law.hires === 399
const requirement = data.getRequirement(law.position_ids[0]);

const references = data.findPositionReferences(
  'moe-bachelor:2026:080901',
  {includeCategoryMembership: true}
);
// 返回候选目录关系及 review_reasons，没有 eligible=true。
```
