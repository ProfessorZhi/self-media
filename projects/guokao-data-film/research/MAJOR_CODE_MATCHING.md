# 专业代码联动：先辨认词元，再建立专业与职位关系

**复核日期：2026-10-17。当前状态：可做词元探索，专业关系尚未修复。**

## 现有数据真正代表什么

`data/2027_position_derived_aggregates.json` 按第三方 `major_codes` 字段聚合出 **649 种代码词元**，涉及 **3,252 / 19,426 条职位记录（16.74%）**。这只是现有清洗器的提取覆盖率，不是专业条件覆盖率；其余 16,174 条不能理解为“不限专业”。

本轮发现两个已经发生的问题：不同学历目录的同码含义被合并；`TK` 尾缀被截断。详见 [机器可读审计](../data/major_code_namespace_audit_2027.json)。总量、地区和税务聚合不因这项发现自动失效，但 **649 不能称作649个已核验专业**。

## 3. P0：当前允许的词元探索镜头

输入仍为 `major_code_mentions.codes`，数字只能解释成“第三方清洗字段中含这个词元的职位记录数/名额数”。

- 一个词元下的省份、系统标签、机构类型边际及省份×系统交叉单元可以分别加总回父节点。
- `name_hints` 是解析提示，含有“开头”“K”等残片，不是可直接播出的标准专业名。
- 歧义词元0809、0812、120401不可强配一个名称；TK异常词元暂不用于命名专业的镜头。
- 030101K可以作为有目录含义说明的技术探索样本：316条职位记录、385名额、30个地区、54个地区×标签单元。仍未逐行核验原始专业分句。
- 未找到词元表示本数据覆盖不足，不代表0个可报岗位。
- 不同词元可能覆盖同一职位；没有行级ID，不能相加、计算交并集或维持跨词元的岗位身份。

**字幕：**“第三方清洗字段词元提及 · 非全部可报岗位”。首次出现与结果卡均应可读；来源说明链接本审计。镜头止于聚合卡，不凭空补出具体岗位。

M1优先拍同源税务筛选。专业镜头保留为单独探索段，待原文与命名空间审核后升级。

## 4. P1：从原文建立可解释的专业关系

最短可靠路径：

1. 先取一个小范围的官方职位附件，记录发布页、下载地址、文件校验和、工作表和行号。
2. 每条保留部门代码、职位代码、`major_raw`、学历、学位及备注；职位唯一键不能只用职位代码。
3. 按“本科：…；研究生：…”分离学历路径，保留文本片段和完整代码，处理TK、括号代码、类别、排除词及不限专业。
4. 按指定目录和年份解释专业含义；类别展开、同名/相近专业、院校自设专业分别留证据。
5. 再用同一批行ID建立专业→地区→机构关系，计算去重后的集合；先验证一个示例，再扩大范围。
6. 专业符合仍不代表全部报考条件符合；学历、学位、应届、经历、政治面貌、备注等另行处理。

优先原件入口：[教育部2027考录职位说明](http://www.moe.gov.cn/s78/A04/tongzhi/202610/t20261014_1454189.html)、[国家移民管理公告及29份附件](https://www.nia.gov.cn/n741440/n741542/c1818347/content.html)。后者链接已整理在 [官方机构JSON](../data/official_2027_immigration_plan.json)，附件本体尚未下载/解析。

## 5. 部门规则不能扩成全国统一规则

[教育部2027职位说明](http://www.moe.gov.cn/s78/A04/tongzhi/202610/t20261014_1454189.html) 适用于教育部的招聘职位。税务有 [2027专用专业参考目录与要求](https://shanghai.chinatax.gov.cn/xxgk/rsxx/202610/t481766.html)，应建立带部门/年份的多对多规则，而非套一个通用前缀。

[国家知识产权局专利局2027报考须知](https://www.cnipa.gov.cn/art/2026/10/14/art_2193_208595.html?xxgkhide=1) 是另一个明确例子：按规定的最高学历报考，仅限硕士职位不接受博士用硕士学历报名；专业名称不完全一致时可结合主要课程综合判断。该例说明专业检索与报考资格之间还有条件，不能把该局规则未经确认推广到所有部门。

## 验收

聚合守恒、目录语义与资格判断是三个独立层次。当前脚本只校验仓库数据及内容卡的一致性，并核对已登记的问题样本；通过不意味着专业语义已修好，也不意味着全国官方原表已逐行核验。
