# 国考数据交接：给 Opus 的事实与读取入口

更新：2026-10-19（第三轮）。本轮目标是交付充足、详实、可追溯的岗位及国考数据；创意与视频表达由 Opus 决定。

**已确立的事实：2027 全国岗位表与官方招考简章工作簿完成 19,426 岗全表逐格核验（27 字段、524,502 单元格、内容差异 0），不再是“仅官方子集 805 岗”。** 专业层有 2026 本科、2022 研究生、两份研究生招生代码册、2026 自设学科名册、2027 税务目录，并把“专业”“备注”两列分开索引、跨字段去重。

**本轮（第三轮）的变化**：残留从 746 降到 728（+18 岗，全部来自纯解析修正而非放宽匹配）；新增 5,835 岗的**互斥复核分层**（十桶相加闭合）与 728 岗的**残留分层**（机关类别 533 / 未核实机关类别 13 / 国家目录词汇 182）。

**现在每个 2027 岗位都有完整专业原文和原始条件；显式代码已从“专业列”扩展到“专业+备注”两列；完整个人报考资格仍未自动判定。**

## 2. 每个岗位有什么

岗位主键示例：`2027:002000:100110001001`。年度、六位部门代码、十二位职位代码都参与主键；单独职位代码只有 7,178 个不同值，会发生碰撞。部门代码的前导零必须保留。

27 个原字段按原始中文列名保存（部门代码、部门名称、用人司局、机构性质、招考职位、职位属性、职位分布、职位简介、职位代码、机构层级、考试类别、招考人数、专业、学历、学位、政治面貌、基层工作最低年限、服务基层项目工作经历、是否在面试阶段组织专业能力测试、面试人员比例、工作地点、落户地点、备注、部门网站、咨询电话1—3）。所有原字段按字符串返回；空单元格、原文“无”“不限”“无限制”分别保存。

`annotations.source_csv_province`、`annotations.source_system_tag` 是第三方注释，来源与原文分开。31 个省级注释都与原工作地点前缀一致，但没有把它提升成完整地理编码认证。

### 4.2 备注列怎么取代码

备注列共 19,172 岗非空，直接套正则会得到电话号码和年份。本轮按上下文过滤：

| 过滤掉 | 次数 |
| --- | ---: |
| 年份（如 2027） | 9,915 |
| 7 位以上长数字（电话） | 1,864 |
| 区号 | 146 |
| 既无目录命中也无专业语境的形状 | 126 |

保留结果：1,069 岗备注含代码提及，366 岗的备注代码可解析到目录；67 岗备注出现精确目录名；706 岗两列都有代码。同一岗位同一代码只计一次，两列来源都保留（238 种代码两列都出现）。

### 4.3 代码形式与“不许合并”的规则

| 形式 | 处理 |
| --- | --- |
| `030100`、`050100` 等四位+`00` | 记为四位学科的招生写法，**不是新专业**（55 种） |
| `030101K`、`030108TK`、`0502100T` | 原样保留后缀与七位码 |
| `0814Z2` 等 Z 码 | 只解析四位前缀，标记为培养单位自设，不编造代码-名称对应 |
| `99J…`、`S…` | 同样标记为机构/自主审核层面代码 |
| 同一六位数在本科/研究生含义不同 | 不合并；按分句学历分别解析，不匹配时记为“越出本学历口径” |
| `会计学类` vs `会计学` | 不做模糊匹配，只有精确目录名才命中 |

### 4.4 代码-名称冲突（逐岗取证）

**口径先说清**：59 是“岗位数”，100 是“冲突条目数”，67 只是三类中的一类。三者不能互换。

- 59 个岗位有代码-名称不一致。其中 54 个产生结构化冲突条目，另 5 个是“门类码与名称错配”（`02法学`），只在 `reason_classes` 记 `gate_code_name_mismatch`，不产生冲突条目。
- 54 个岗位共产生 100 条冲突条目：`content_conflict` 67、`cross_level_same_code` 25、`category_suffix_omitted` 8。
- 涉及 96 个不同代码。

| 冲突类型 | 条数 | 含义 |
| --- | ---: | --- |
| `cross_level_same_code` | 25 | 同一代码在另一学历层另有名称（如 080401 本科=材料科学与工程、研究生=精密仪器及机械） |
| `category_suffix_omitted` | 8 | 原文省略“类”字（如 0203 = 金融学类） |
| `content_conflict` | 67 | 名称属于另一个代码（如 `120202财务管理`，120202 实为企业管理） |

每条冲突都带 `field`、代码、跨度、目录名称、印刷名称与上下文原文，可逐岗回放。

### 4.5 排除项

600 个岗位的专业列含 `不含/除/不包括` 括号清单。这些名称**不计入覆盖**，只作为排除证据保留（`major_excluded_names`）。例如“经济金融类（不含统计、国际商务、资产评估…）”里的国际商务是排除项，不是可报专业。

### 4.6 两条有据可查的归一规则

本轮只新增两条归一，都有书面依据，不做相似度匹配：

| 规则 | 触发写法 | 依据 |
| --- | --- | --- |
| `gate_scope_rule` | “法学门类”“工学学科门类” | 教育部《关于教育部2027年度公务员考录职位要求的说明》（2026-10-14）：学科门类要求覆盖该门类下的专业与一级学科 |
| `source_declared_gate_code` | “经济学类（02）”“专业代码前两位为02” | 职位原文自带两位门类代码，等于自定范围 |

三条依据各自的适用范围要分开看：

| 依据 | 适用范围 | 本项目的用法与风险 |
| --- | --- | --- |
| 教育部 2027 职位要求说明 | 文本只针对**教育部**职位 | 只借用“门类覆盖其下专业与一级学科”这一通行语义；把它推广到其他机关属于**推定**，不是全国性规定。本轮已把这类岗位单独标记，便于剔除对比 |
| 职位原文自带两位门类代码 | 该岗位自身 | 最稳：原文自定范围 |
| 单位/单个专业名 + “或”与“等专业” | 该岗位自身 | 纯解析修正：`会计学或审计学或财务管理` 按“或”切分；`财务管理等专业` 去掉开放尾巴取精确名。列表开放时保留 `open_scope` 标记 |

门类归一在 183 岗留证（门类写法 69、原文自带代码 145，31 岗重叠）。**本轮真实增量 +18 岗来自“或”切分（2）与“等专业”尾巴（16）**，不来自门类推广。

**没有做的归一**：`理学类`（门类名加口语“类”）、`会计学类`、研究生岗位中的本科类别名（如“中国语言文学类”）都只分类、不解析。

### 4.8 机关类别为什么清不掉

已逐项核查公开来源，结论是**没有适用于 2027 公务员岗位的成员名单**：

### 4.9 复核状态分层（5,835 岗，互斥）

5,835 是**旧三层目录时代**“带复核原因”的分母，不是未覆盖数。本轮为每个岗位只给一个桶，十桶相加恰为 5,835：

| 桶 | 岗位 | 含义 |
| --- | ---: | --- |
| `candidate_with_degree_scope` | 1,994 | 有候选；分句/学历口径仍需判断 |
| `candidate_with_open_scope` | 1,234 | 有候选；含“相关/等专业/方向”开放表述 |
| `candidate_legacy_reason_superseded` | 997 | 有候选；旧层告警在现行层不再复现（**不等于已核清**） |
| `candidate_with_namespace_ambiguity` | 501 | 有候选；同名多个目录节点 |
| `candidate_with_exclusion` | 276 | 有候选；含否定/排除（排除项已单独保留） |
| `no_candidate_agency_no_public_list` | 533 | 无候选；机关类别，已核实无公开成员表 |
| `no_candidate_other` | 182 | 无候选；国家目录词汇或开放表述 |
| `no_candidate_agency_unverified` | 13 | 无候选；机关类别，发布状态未核实 |
| `candidate_with_conflict` | 59 | 有候选；代码旁名称与目录矛盾（54 结构化 + 5 门类码错配） |
| `candidate_with_unresolved_vocabulary` | 46 | 有候选；仍有词项未解析 |

三条使用纪律：

1. **有一条候选 ≠ 整岗已核清**。997 个“旧告警不再复现”只说明本工具换了目录后不再报警。
2. **5,835 ≠ 未覆盖**。真正的未覆盖是 728（三个 no_candidate 桶）。
3. **风险标优先**：`candidate_with_conflict`、`candidate_with_exclusion`、`candidate_with_degree_scope`、`candidate_with_namespace_ambiguity` 这四类在桶里优先于普通开放表述，逐岗记录同时带 `risk_flags`。

逐岗记录：`data/major_evidence_2027/review-status-*.json`；汇总见 [REVIEW_STATUS_20261019.json](research/REVIEW_STATUS_20261019.json)，残留分层见 [RESIDUAL_STRATA_20261019.json](research/RESIDUAL_STRATA_20261019.json)。

## 5. 反向查询

```bash
# 完整代码 → 真实岗位与计划人数
node scripts/query_major_evidence.mjs --code 030101K

# 精确目录名（可加学历过滤）
node scripts/query_major_evidence.mjs --name 世界经济 --education graduate

# 目录节点 → 岗位
node scripts/query_major_evidence.mjs --catalog moe-bachelor:2026:080901

# 单个岗位的全部证据
node scripts/query_major_evidence.mjs --position 2027:002000:100110001001

# 残留清单，可按原因、机关与原文过滤
node scripts/query_major_evidence.mjs --residual --reason exclusion_list_present --text 经济金融类
```
