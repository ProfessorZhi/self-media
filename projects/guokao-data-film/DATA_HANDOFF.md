## 2. 每个岗位有什么

岗位主键示例：`2027:002000:100110001001`。年度、六位部门代码、十二位职位代码都参与主键；单独职位代码只有 7,178 个不同值，会发生碰撞。部门代码的前导零必须保留。

### 4.3 代码形式与“不许合并”的规则

| 形式 | 处理 |
| --- | --- |
| `030100`、`050100` 等四位+`00` | 记为四位学科的招生写法，**不是新专业**（55 种） |
| `030101K`、`030108TK`、`0502100T` | 原样保留后缀与七位码 |
| `0814Z2` 等 Z 码 | 只解析四位前缀，标记为培养单位自设，不编造代码-名称对应 |
| `99J…`、`S…` | 同样标记为机构/自主审核层面代码 |
| 同一六位数在本科/研究生含义不同 | 不合并；按分句学历分别解析，不匹配时记为“越出本学历口径” |
| `会计学类` vs `会计学` | 不做模糊匹配，只有精确目录名才命中 |

### 4.3.1 备注中的学历作用域（本轮新增）

备注经常自己指定学历层级，例如：

```text
本科专业应为：0702物理学类、080204机械电子工程、080210T微机电系统工程……
1．本科阶段为会计学（学科代码120203K）、审计学（学科代码120207）专业，或研究生阶段为法学（学科代码0301）
本职位所指本科专业代码为0703、0817、0827、0901……
```

旧逻辑一律按岗位「学历」栏解析，于是研究生岗位里出现的本科代码被当成研究生代码，产生**假冲突**（`cross_level_same_code`）。

现在的规则：

| 情形 | 处理 | 记录字段 |
| --- | --- | --- |
| 显式且有边界的标签：`本科专业`/`本科阶段`/`本科专业代码为`/`本科：`/`研究生专业`/`研究生阶段`/`研究生：`/`博士研究生专业` | 该标签管辖的跨度内按对应层级解析 | `scope_source=explicit_label`、`scope_text`、`scope_span` |
| 无标签 | 回退到岗位学历（原逻辑） | `scope_source=fallback_position_education` |
| 混合标签：`本科或研究生阶段`、`本科、研究生专业` | **同样回退**到岗位学历，不放大到两级，并标风险 | `scope_source=ambiguous_mixed_degree_label` |

作用域边界：到下一个标签、句号/分号/换行为止，最长 120 字。因此“本科专业代码为0703、0817…”这一串整段归属本科，“；研究生：020203…”归属研究生。

规模：1,832 处备注代码中，**712 处由显式标签定层**、1,105 处回退、15 处因混合标签回退并标记。

**这仍然不是资格判断**：本科条件与研究生条件可以同时存在，本数据只记录“这句话在说哪一层”，不判断某人是否两层都满足。

前后差异见 [备注作用域修复对照](research/REMARK_SCOPE_FIX_DIFF_20261018.json)。

### 4.5 排除项

600 个岗位的专业列含 `不含/除/不包括` 括号清单。这些名称**不计入覆盖**，只作为排除证据保留（`major_excluded_names`）。例如“经济金融类（不含统计、国际商务、资产评估…）”里的国际商务是排除项，不是可报专业。

### 4.6 门类推定与门类直接证据（本轮收紧）

`gate_scope_rule` 依据的是教育部《关于教育部2027年度公务员考录职位要求的说明》（2026-10-14）。**这份文件的适用对象是教育部自己的职位，不是全国统一资格政策。**

三条依据的适用范围必须分开看：

| 依据 | 适用范围 | 本项目怎么用 |
| --- | --- | --- |
| 教育部 2027 职位要求说明 | 文本只针对**教育部**职位，不是全国资格政策 | 只借用“门类覆盖其下专业与一级学科”的读法；**用于非教育部岗位属于推定** |
| 职位原文自带两位门类代码 | 该岗位自身 | 直接证据，计入保守覆盖 |
| `或` / `等专业` 分隔符处理 | 该岗位自身 | 纯解析修正 |
| “X类”（如理学类、中国语言文学类） | 不属于任何一条依据 | 不解析，只分类 |

**本轮的关键收紧**：`gate_scope_rule` 的 95 处命中**没有一处属于教育部岗位**（全部是国家金融监督管理总局各监管局、海事局、海关、铁路监管局）。因此该规则已被移出保守覆盖分子，改为 **provisional**：原文与门类节点照常记录，但状态标为 `agency_scope_unverified`，逐岗清单见 [范围审计](research/FINAL_EVIDENCE_SCOPE_AUDIT_20261018.json) 的 `provisional_positions`。

| 口径 | 岗位 |
| --- | ---: |
| 保守覆盖（不含推定） | 18,680 |
| 仅靠门类推定（provisional） | 19 |
| 含推定的口径 | 18,699 |
| 无任何候选 | 727 |

`source_declared_gate_code`（原文写“02”）不受此项影响：145 个岗位的两位代码是原文自己写的，属于直接证据，计入保守覆盖。

**没有做的归一**：`理学类`（门类名加口语“类”）、`会计学类`、研究生岗位中的本科类别名（如“中国语言文学类”）都只分类、不解析。

### 4.8 机关类别为什么清不掉

已逐项核查公开来源。**截至 2026-10-18 的已查来源，未找到适用于 2027 公务员岗位的成员名单**——这是“未找到”，不是“不存在”；未列入的机关只记为未核实。

这不是工具缺陷：数据层已能解析代码与精确名称，缺的是本次核查范围内未找到的类别成员定义。完整取证记录见 [机关类别证据](research/AGENCY_MAJOR_CATEGORY_EVIDENCE_20261018.json)，v1→v2 的可复核 delta 与残留分层见 [残留报告 v2](research/RESIDUAL_20271018_V2.json)。

| `candidate_with_exclusion` | 276 | 有候选；含否定/排除（排除项已单独保留） |
| `no_candidate_agency_no_public_list` | 533 | 无候选；机关类别，已查来源未找到 2027 适用名单 |
| `no_candidate_other` | 181 | 无候选；国家目录词汇或开放表述 |
| `no_candidate_agency_unverified` | 13 | 无候选；机关类别，发布状态未核实 |
| `candidate_with_conflict` | 55 | 有候选；**复核域内** 50 个结构化冲突岗 + 5 个门类码错配岗（全库结构化冲突为 54 岗，两者集合不同） |
| `candidate_with_unresolved_vocabulary` | 46 | 有候选；仍有词项未解析 |

三条使用纪律：

1. **有一条候选 ≠ 整岗已核清**。981 个“旧告警不再复现”只说明本工具换了目录后不再报警；19 个 provisional 只是推定命中。
2. **5,835 ≠ 未覆盖**。真正的未覆盖是 727（三个 no_candidate 桶）。
3. **风险标优先**：`candidate_with_conflict`、`candidate_with_exclusion`、`candidate_with_degree_scope`、`candidate_with_namespace_ambiguity` 这四类在桶里优先于普通开放表述，逐岗记录同时带 `risk_flags`。

逐岗记录：`data/major_evidence_2027/review-status-*.json`；汇总见 [REVIEW_STATUS_20261018.json](research/REVIEW_STATUS_20261018.json)，残留分层见 [RESIDUAL_STRATA_20261018.json](research/RESIDUAL_STRATA_20261018.json)。
